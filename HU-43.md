# HU-43 - Registrar automáticamente los datos de auditoría en cada transacción

**Historia**: Como responsable de la organización (Administrador), quiero que toda entidad y transacción del sistema registre obligatoriamente sus datos de auditoría, para poder determinar en cualquier momento quién realizó una modificación y cuándo, garantizando la integridad y la responsabilidad sobre los datos.

**Criterios de Aceptación**: 

- Dado que se crea un nuevo registro de cualquier entidad auditable del sistema (usuarios, neumáticos, unidades de transporte, conductores, proveedores, servicios de reparación, centros de almacenamiento), cuando la operación se confirma, entonces el sistema debe registrar automáticamente el usuario autenticado que realizó la acción y la fecha/hora de creación, sin intervención manual del usuario.
- Dado que se modifica un registro existente de una entidad auditable, cuando la operación se confirma, entonces el sistema debe actualizar automáticamente el usuario y la fecha/hora de última modificación.
- Dado que se da de baja (lógicamente) un registro de una entidad auditable, cuando la operación se confirma, entonces el sistema debe registrar el usuario y la fecha/hora de la baja, sin eliminar físicamente el registro de la base de datos.
- Dado que un usuario con permisos adecuados (Administrador) consulta el historial de auditoría de un registro específico, entonces el sistema debe permitirle visualizar dicha metadata (usuario y fechas de creación/modificación/baja).
- Dado que un usuario con nivel de acceso Lector o Editor intenta acceder a esta funcionalidad de visualización, entonces el sistema debe denegar el acceso a dicha pantalla o funcionalidad.

**Notas / Supuestos**: Se trata de un requisito transversal implementado técnicamente a nivel de infraestructura, por lo que en la práctica constituye una tarea de arquitectura que da soporte a todas las demás historias funcionales, en lugar de una funcionalidad visible de forma aislada para el usuario final.
